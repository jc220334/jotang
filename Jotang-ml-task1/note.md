# 1. 你在这个任务之中，选择了什么激活函数，为什么选这个？

选择了ReLU作为激活函数，因为ReLU解决了Sigmoid/Tanh的梯度消失问题，让深层网络能训起来，同时ReLU的计算极快，在这里最省事

补充几点：

- 公式就是 `f(x) = max(0, x)`：前向只做一次比较，反向的导数要么是 1、要么是 0，
  不像 Sigmoid/Tanh 那样在两端把梯度“压扁”，所以深层也能训得动。
- 顺带还有“稀疏激活”的效果：负半轴输出直接为 0。
- 代价是可能出现“神经元死亡”（某个神经元恒输出 0、梯度恒为 0）。真遇到了可以换成 LeakyReLU。
- 本脚本里隐藏层全用 ReLU，输出层不加激活函数（直接输出 logits），因为配的是 CrossEntropyLoss。

# 2. 你选择了什么损失函数？为什么？那如果这一题是三分类问题呢？

选了 **CrossEntropyLoss（交叉熵损失）**。因为这是**多分类**问题（这里是 2 类），
交叉熵正好衡量“模型预测的概率分布”与“真实 one-hot 标签”之间的差距，是分类任务的标准选择。

- 配合方式：网络的输出层输出 **logits**（不加 softmax），`CrossEntropyLoss` 内部会自动做
  `LogSoftmax + NLLLoss`。把 softmax 合进损失里是**数值上更稳定**的做法（省掉了概率可能会出现
  的 log(0)、溢出等问题）。
- 梯度很干净：对 logits 的导数就是 `p - y`（预测概率减去真实标签），和 SGD/Adam 配合很好。

**如果改成三分类**，只需要动输出层一个地方：

```python
nn.Linear(hidden_width, 3)        # 原来是 nn.Linear(hidden_width, 2)
```

标签仍然用 0/1/2 的 `torch.long` 张量，**损失函数一行都不用改**——CrossEntropyLoss 本来就是
为“任意类别数的多分类”设计的，它按输出维度做归一化。

顺便区分两种容易混的情况：

- 三个类别**互斥**（一个样本只属于一个类）→ softmax + CrossEntropyLoss，就是我们现在的做法。
- 一个样本**可以同时属于多个类**（多标签）→ 应该用 `BCEWithLogitsLoss`，输出维度也是 3，
  但每个维度独立做 sigmoid、独立算二分类交叉熵。

另外二分类也可以只输出 1 个值配 `BCEWithLogitsLoss`；本脚本用“2 个 logits + CE”的写法，
好处是和三分类的代码结构完全统一，改类别数时最省事。

# 3. `optimizer.zero_grad()`、`loss.backward()` 和 `optimizer.step()` 分别完成了什么工作？如果不清空梯度会发生什么？

- `optimizer.zero_grad()`：把模型所有参数的 `.grad` 清干净，为这一轮反向传播准备一个“空的梯度桶”。
- `loss.backward()`：从 loss 出发做反向传播（链式法则），把每个参数的偏导数
  **累加**到 `param.grad` 上。注意 PyTorch 的语义是**累加**，不是覆盖。
- `optimizer.step()`：读出 `param.grad`，按优化器自己的规则更新参数
  （Adam 大致是 `p ← p - lr · m̂ / (√v̂ + ε)`），它**不会**自动清空梯度。

**如果不清空梯度**：因为 `backward()` 是累加的，上一个 batch 的梯度会残留下来，等于把很多个
batch 的梯度加在一起，等效于用了一个越来越大、而且和历史纠缠不清的更新量。表现就是训练剧烈
震荡、难以收敛，甚至直接发散。所以标准顺序永远是：

```python
optimizer.zero_grad()   # 1. 清空旧梯度
loss = criterion(model(xb), yb)
loss.backward()         # 2. 累加新梯度
optimizer.step()        # 3. 用梯度更新参数
```

小补充：新版 PyTorch 的 `zero_grad()` 默认是 `set_to_none=True`，把 `.grad` 设成 `None` 而不是
全 0 张量，能省一点点内存。另外，清梯度也可以写在循环末尾（下一个 batch 开头），效果一样。

# 4. 更深、更宽的神经网络一定能取得更好的效果吗？模型过于简单或过于复杂分别可能带来什么问题？

**不一定。** 参数量代表的是“容量”，能不能变成效果，取决于数据量、数据本身的可分程度、
有没有正则化、以及训练是否充分。本任务里就有现成的反例：任务 4 的对照实验中，把隐藏层宽度
从 8 加到 128，参数量从 114 涨到 17154（约 150 倍），测试准确率反而从 **0.9900 掉到 0.9750**。

- **过于简单（欠拟合）**：容量不足以刻画数据的真实规律，训练集和验证集**都不好**，
  loss 降到某个水平就再也下不去。对照表里“隐藏层数 1”的验证准确率 0.9500、
  “学习率 1e-3”只有 0.9437，都属于这一类。
- **过于复杂（过拟合）**：模型把训练集里的噪声和偶然细节也背了下来，训练集表现很好、
  验证/测试集明显变差，两者差距拉大。第 7 题的实验里，30 个样本训 13 万参数的网络，
  训练准确率 100%、验证只有 90.8%。
- 另外还有**代价问题**：更宽更深意味着参数更多、训练更慢（对照表里 batch=16 那项耗时 2.83s，
  是基线 1.11s 的两倍多），部署和推理也更重。

所以正确顺序是：先用一个**够用的**小模型把基线跑出来，再根据训练/验证曲线的差距决定要不要加大。
判断“过简单还是过复杂”，最直接的办法就是看这两条曲线的**差距和走向**。

# 5. 学习率过大或过小会怎样影响模型训练？你能从 loss 曲线中观察到哪些现象？

- **学习率过大**：每步迈得太大，容易直接跨过最优点。loss 曲线的典型现象是
  **剧烈震荡、上下跳动**，甚至不降反升、最后变成 NaN（发散）。
- **学习率过小**：每步只挪一点点，loss 曲线**下降得很慢但很平滑**，同样的 epoch 数下
  根本没收敛。任务 4 里把 lr 从 1e-2 降到 1e-3，跑 60 个 epoch 后验证准确率只有 0.9437，
  这就是“不是模型不行，是还没训够”的典型表现。
- **合适的学习率**：loss 先快速下降，然后平稳地收敛到一个较低的值，训练/验证两条曲线
  都趋于平缓且离得不太远。
- 实践中还可以配合**学习率调度**：前期大一点、后期小一点（StepLR / CosineAnnealingLR 等），
  比全程一个固定值更容易收敛到好解。这也是观察 loss 曲线的实际用途之一——
  曲线震荡就把 lr 调小，曲线太“平”就调大或加 epoch。

# 6. 假设还有一个分类问题，但是两个类别的样本数量非常不均衡，训练出来的模型会怎么样？为什么？说明了什么？（我构造数据集试了）

我构造了一个约 **1 : 25** 不均衡的 moons 数据集：少数类（类别 0）只保留 **40** 个样本，
多数类（类别 1）保留 **1000** 个，并把噪声从 0.2 提到 0.3 让边界更难分；然后用任务 2 的
同一套 MLP 训练 100 个 epoch。测试集结果：

```
混淆矩阵（行 = 真实 0/1，列 = 预测 0/1）：
[[  6   6]
 [  1 299]]

整体准确率                    = 0.9776
“无脑全猜多数类”的准确率      = 0.9615     <-- 对比用
少数类 0 的召回率             = 0.5000
多数类 1 的召回率             = 0.9967
```

（混淆矩阵图见 `note_imbalanced_cm.png`，实验脚本见 `note_experiments.py`）

**观察到的现象：**

1. 整体准确率看起来很高（97.8%），但**几乎不比“全猜多数类”的 96.2% 好多少**。
   在不均衡数据上，accuracy 本身就是个会骗人的指标。
2. 少数类的召回率只有 **50%**——一半的少数类样本被当成多数类吃掉了；而多数类几乎全对。
3. 少数类的 precision 反而挺高（0.86），说明模型只在“很有把握”时才敢判少数类，
   其余时候一律倒向多数类。

**为什么：** 交叉熵是**对所有样本求平均**的。多数类样本占了绝大多数，只要把多数类分对，
loss 就能被压得很低；而边界附近那些样本判成多数类的期望损失更小。所以模型会**牺牲少数类**
去换整体 loss 的下降。

**说明了什么：** 评估不均衡问题不能只看 accuracy，要看**每个类别的 precision / recall / F1
（尤其 macro 平均）和混淆矩阵**。想缓解的话可以：给少数类加权
（`CrossEntropyLoss(weight=...)`）、过采样少数类 / 欠采样多数类、或者用 focal loss；
划分数据时继续用 `stratify` 保证各集合里比例一致。

# 7. 如果想要过拟合这个数据集，你会怎么做？为什么？试试看能不能实现！（我试了）

**我的做法（实验 B）**，三条一起上，目的就是让“模型容量”远远超过“数据提供的信息量”：

1. 把训练样本压到极少：**只用 30 个样本训练**，另外 185 个样本留作验证（同一分布）。
2. 把模型做大：**3 个隐藏层 × 256 宽**，参数量 **132866**；对比一下，数据只有 30 个点。
3. 训练很久：**800 个 epoch**，而且**不加任何正则化**（没有 weight_decay / dropout / 早停）。

**结果（可以对照 `note_overfit_curves.png`、`note_overfit_compare.png`）：**

```
第 12 个 epoch 验证损失最低：0.3001（此时验证准确率 0.9027）
训练结束时：训练 Loss = 0.0000，训练 Acc = 1.0000
            验证 Loss = 1.4468，验证 Acc = 0.9081
训练与验证准确率差距 = +0.0919

对照（同样的小数据，换成 1 层 × 8 宽的小模型，200 epoch）：
训练 Acc 0.9000 / 验证 Acc 0.8649，差距只有 +0.0351
```

**训练过程和正常训练有何不同：**

- **训练 loss 一路降到 0，而验证 loss 先降后升**：最低点出现在第 12 个 epoch（0.30），
  之后一路涨到 1.45。正常训练里这两条线是相伴下降、最后一起平掉的，不会“分叉”。
- 训练准确率先冲到 100%，验证准确率却卡在 90% 左右不再提高，两条线之间张开一个口子。
- 验证 loss 的最低点出现在训练的**很早期**，这正是 early stopping 想抓住的位置。

**我通过什么判断它过拟合：**

1. 训练集与验证集指标差距持续拉大（训练 100% vs 验证 90.8%）；
2. 验证 loss 已经过了最低点开始单调回升，而训练 loss 还在继续下降；
3. 从容量上看：30 个训练样本 vs 13 万参数，模型完全有能力把训练集“背下来”。

反过来，防过拟合的手段就是针对这三点：增加数据 / 数据增强、把模型改小、加 L2 正则
（`weight_decay`）、加 Dropout、以及早点停（early stopping）。比如把训练停在验证损失最低的
第 12 个 epoch，验证准确率反而更好。
