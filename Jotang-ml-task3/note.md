# 1. 把计算过程拆成若干简单步骤，并画出计算图

## 拆成 4 步

| 顺序 | 节点 | 前向公式 | 这一步在算什么 |
| --- | --- | --- | --- |
| ① | `a` | $a = x^2$ | 题目里的 $x^2$ |
| ② | `b` | $b = x \cdot y$ | 题目里的 $xy$ |
| ③ | `u` | $u = a + b$ | 题目括号里的 $xy + x^2$ |
| ④ | `f` | $f = u^2$ | 整体平方，最终输出 |

代入数值：

```
a = x²  = (1.5)²         = 2.25
b = x·y = 1.5 × (-2)     = -3.0
u = a+b = 2.25 + (-3.0)  = -0.75      ← xy + x²
f = u²  = (-0.75)²       = 0.5625     ← 最终输出
```

## 为什么拆到这一步就够了

拆分的标准只有一个：**每个节点都只用一种"导数能直接背出来"的基本运算**。这次用到的只有四种：

| 基本运算 | 局部导数（对自己输入的导数） |
| --- | --- |
| 平方 $y = x^2$ | $\dfrac{dy}{dx} = 2x$ |
| 乘法 $z = x \cdot y$ | $\dfrac{\partial z}{\partial x} = y,\ \dfrac{\partial z}{\partial y} = x$（用**对方**的局部导数） |
| 加法 $z = x + y$ | $\dfrac{\partial z}{\partial x} = \dfrac{\partial z}{\partial y} = 1$ |
| 常数倍 | 常数本身 |

拆到这一层以后，整条链的导数就是这四张公式表乘来乘去，不需要现场推任何东西。如果再往下拆
（比如把 $x^2$ 拆成 $x \cdot x$），图会更长，但结论一模一样——拆的粒度取决于你想要多细的粒度，
不取决于对错。

还有一个关键结构：**$a$ 和 $b$ 都用到了 $x$**。也就是说 $x$ 这个节点在图上长了两条出边，
这在反向传播里叫**扇出（fan-out）**，意味着 $x$ 处要把两条路径带回来的梯度**相加**，
而不是后算的把先算的覆盖掉。这一点是所有"梯度算错"里最常见的来源，第 2 节会用数字摊开说明。

## 计算图

箭头方向 = 数据的流动方向（前向从左往右，反向从右往左）：

```
   ┌──────────┐
x ─┤  a = x²  ├─┐
   └──────────┘ │   ┌───────────┐      ┌─────────┐
                ├──►│  u = a+b  ├─────►│  f = u² │
   ┌──────────┐ │   └───────────┘      └─────────┘
x ─┤  b = x·y ├─┘
y ─┤          │
   └──────────┘
```

（把 $x$ 画两个框只是为了边不交叉；它们其实是同一个节点，所以反向时梯度要汇合相加。）

实际画出来的版本见 `01_compute_graph.png`，左半张是前向（框里写每一步算出的数值），
右半张是反向（红箭头是梯度回传方向，边上的标签是这一步的局部导数，框里是流到该点的 $\partial f/\partial\cdot$）。

## 计算图这个概念到底解决什么问题

写成一行 `f = (x*y + x**2)**2` 的时候，"怎么求导"是隐式的：得靠人去做代数化简。
画成计算图之后，求导变成一条**纯机械的规则**：

> 从输出出发，沿着边往回走；每经过一个节点，就把带下来的梯度乘以该节点自己的局部导数。
> 遇到一个节点有多条出边，就把各条路径的结果相加。

这条规则里没有"代数技巧"这一项，所以可以交给程序按图执行——PyTorch 的 autograd 干的就是这件事，
它做的事情在第 3 节可以直接打印出来看。

# 2. 用 NumPy 按计算图从后往前计算梯度

## 反向的顺序

反向顺序正好是前向的倒序：$f \to u \to (a, b) \to x, y$。起点是 $\partial f/\partial f = 1$，
因为梯度是从输出往回流的，输出自己对自己的导数就是 1。

## 逐步计算

**反向第 1 步｜经过节点 $f = u^2$**

$$\frac{\partial f}{\partial u} = 2u = 2 \times (-0.75) = -1.5$$

注意这里 $u$ 是负数，所以导数是负的——这就是选 $y = -2$ 想验的点。

**反向第 2 步｜经过节点 $u = a + b$**

加法的局部导数都是 1，等价于"把带下来的梯度原样分给两个输入"：

$$\frac{\partial f}{\partial a} = \frac{\partial f}{\partial u}\cdot 1 = -1.5,\qquad
\frac{\partial f}{\partial b} = \frac{\partial f}{\partial u}\cdot 1 = -1.5$$

**反向第 3 步｜分别经过 $a = x^2$ 和 $b = x\cdot y$**

沿 $a$ 这条路径回到 $x$：

$$\frac{\partial a}{\partial x} = 2x = 3 \;\Longrightarrow\;
\text{这条路径带给 } x \text{ 的贡献} = \frac{\partial f}{\partial a}\cdot\frac{\partial a}{\partial x}
= (-1.5) \times 3 = -4.5$$

沿 $b$ 这条路径：乘法的两个输入各用**对方**当局部导数，所以 $\partial b/\partial x = y$、$\partial b/\partial y = x$：

$$\frac{\partial b}{\partial x} = y = -2 \;\Longrightarrow\; \text{带给 } x \text{ 的贡献} = (-1.5)\times(-2) = 3.0$$

$$\frac{\partial b}{\partial y} = x = 1.5 \;\Longrightarrow\; \frac{\partial f}{\partial y} = (-1.5)\times 1.5 = -2.25$$

这里有两个符号陷阱叠在一起：$u$ 是负的（梯度本身带负号），$y$ 也是负的（乘法的局部导数为负），
两次取负之后 $b \to x$ 这条路径的贡献变成了正的 $+3.0$。

**汇聚｜$x$ 处两条路径相加**

$$\frac{\partial f}{\partial x} = \underbrace{(-4.5)}_{\text{经 } a = x^2} + \underbrace{(3.0)}_{\text{经 } b = x\cdot y} = -1.5$$

如果这里忘了相加、直接留下最后算出来的那个数，就会得到 $-4.5$ 或 $3.0$（取决于遍历顺序），
和正确答案差得很远。而且这种错误很阴险：图简单的时候人会记得，图一深就会忘，
所以框架里把它固化成了"每条边回传时累加"，我们手写的时候也要照着做。

## 代码

前向和反向就是照着计算图一行行写下来的（`compute_graph.py` 里去掉打印的部分）：

```python
def forward_numpy(x, y):
    a = x ** 2          # 节点 a：x 的平方
    b = x * y           # 节点 b：x 乘以 y
    u = a + b           # 节点 u：加法
    f = u ** 2          # 节点 f：u 的平方（最终输出）
    return {"a": a, "b": b, "u": u, "f": f}


def backward_numpy(x, y, cache):
    a, b, u = cache["a"], cache["b"], cache["u"]
    grads = {}

    grads["f"] = 1.0                            # 起点 ∂f/∂f = 1

    grads["u"] = grads["f"] * (2.0 * u)         # 经过 f = u²   → ∂f/∂u = 2u
    grads["a"] = grads["u"] * 1.0               # 经过 u = a+b  → ∂u/∂a = 1
    grads["b"] = grads["u"] * 1.0               # 经过 u = a+b  → ∂u/∂b = 1

    grad_from_a = grads["a"] * (2.0 * x)        # 经过 a = x²   → ∂a/∂x = 2x
    grad_from_b = grads["b"] * y                # 经过 b = x·y  → ∂b/∂x = y
    grads["y"] = grads["b"] * x                 # 经过 b = x·y  → ∂b/∂y = x

    grads["x"] = grad_from_a + grad_from_b      # 扇出：两条路径相加
    return grads, grad_from_a, grad_from_b
```

每一行都严格对应图上的一条边："上游梯度 × 这条边的局部导数"。整个反向过程**没有做任何代数化简**，
用的全是第 1 节那四张基本导数表。

## 结果与交叉验证

$$\frac{\partial f}{\partial x} = -1.5,\qquad \frac{\partial f}{\partial y} = -2.25$$

先用手推的解析式核对一遍。把 $f = u^2,\ u = xy + x^2$ 直接展开求导：

$$\frac{\partial f}{\partial x} = 2u \cdot (y + 2x) = 2(xy + x^2)(y + 2x) = 2\times(-0.75)\times(1) = -1.5$$

$$\frac{\partial f}{\partial y} = 2u \cdot x = 2x(xy + x^2) = 2\times 1.5\times(-0.75) = -2.25$$

和按图回传的结果一致。

# 3. 用 PyTorch 的 autograd 检查结果是否一致

## 代码

为了能一一对应，我先用**和手写版完全相同的 4 步写法**建图：

```python
tx = torch.tensor(x, dtype=torch.float64, requires_grad=True)
ty = torch.tensor(y, dtype=torch.float64, requires_grad=True)

a = tx ** 2        # 对应我们图上的节点 a
b = tx * ty        # 对应节点 b
u = a + b          # 对应节点 u
f = u ** 2         # 对应节点 f

f.backward()       # 从 f 出发自动做反向传播
tx.grad, ty.grad   # 结果就在这里
```

再用一行写完的版本 `f = (tx*ty + tx**2)**2` 跑一次——两种写法结果**逐位相同**
（用 `float.hex()` 比对过，都是 `-0x1.8000000000000p+0` 和 `-0x1.2000000000000p+1`）。
这不是巧合：两者的浮点乘加顺序完全一样，autograd 只是把我们手写的那几行自动拆成了同一张图。

## 三方对照

| 求的对象 | NumPy 按计算图手写 | 中心差分数值梯度 | PyTorch autograd | 手写 vs autograd 绝对误差 |
| --- | --- | --- | --- | --- |
| $\partial f/\partial x$ | -1.5 | -1.4999999999 | -1.5 | 0.00e+00 |
| $\partial f/\partial y$ | -2.25 | -2.2500000000 | -2.25 | 0.00e+00 |

前向值也一致：手写 $f = 0.5625$，PyTorch $f = 0.5625000000$。

## autograd 自己建出来的图长什么样

把 `f.grad_fn` 顺着 `next_functions` 打出来：

```
- PowBackward0          ← 我们的节点 f = u²
  - AddBackward0        ← 我们的节点 u = a + b
    - PowBackward0      ← 我们的节点 a = x²
      - AccumulateGrad  ← 汇入 x 的 .grad（其中一条路径）
    - MulBackward0      ← 我们的节点 b = x·y
      - AccumulateGrad  ← 汇入 x 的 .grad（另一条路径）
      - AccumulateGrad  ← 汇入 y 的 .grad
```

这张自动生成的图和我们在纸上画的图是同一个东西：两个 `PowBackward0` 对应两个平方节点，
`MulBackward0` 对应乘法节点，`AddBackward0` 对应加法节点。而 `AccumulateGrad` 出现了两次挂在
同一个 $x$ 上——这正是 PyTorch 对"扇出"的实现方式：**每条边回传时往对应变量的 `.grad` 里累加**
（默认是 `+=`，这也是为什么训练循环里必须 `optimizer.zero_grad()` 清空梯度，Task 1 的笔记里写过这件事）。
我们手写的 `grads["x"] = grad_from_a + grad_from_b` 就是这一行的等价物。

## 随机多测几组

只有一组数对上是有可能碰巧的（尤其是这组数都是"漂亮数"）。所以脚本又随机抽了 20 组
$(x, y) \in [-3, 3]^2$，每组都跑三方对比：

```
手写反向 vs autograd     最大绝对误差：0.00e+00
手写反向 vs 中心差分     最大绝对误差：7.48e-08
```

* 手写与 autograd 的误差是 **0**，一个 bit 都不差——因为两边做的是同一串浮点运算、同样的顺序，
  连舍入误差都一样。
* 数值梯度的 7.48e-08 不是错误，是方法本身的精度。中心差分的误差由两部分组成：
  截断误差 $O(h^2)$（$h = 10^{-6}$ 时只有 $10^{-11}$ 量级，可以忽略），
  以及主导的舍入误差 $\sim \frac{\varepsilon \cdot |f|}{2h}$。这 20 组里梯度最大的那组 $|f| \approx 306$，代入
  $\frac{2.2\times 10^{-16} \times 306}{2\times 10^{-6}} \approx 3.4\times10^{-8}$，与实测同量级；
  换成相对误差看是 $5\times10^{-10}$。
  也就是说数值梯度这类方法只能验到 1e-8~1e-10 的绝对精度，想验"公式对不对"完全够用，
  但想验"最后一位对不对"就不行了——那得靠解析式和 autograd 互相印证。

# 4. 这次手写反向传播最容易踩的坑（自查清单）

1. **平方节点的导数漏符号**：$\partial f/\partial u = 2u$，$u$ 为负时结果就是负的。
   本例 $-1.5$，如果写成 $|2u|$ 或忘了符号，后面全错。
2. **乘法节点用错局部导数**：$\partial b/\partial x = y$、$\partial b/\partial y = x$，
   对着 $x$ 求导时用的是 $y$。写成 $\partial b/\partial x = x$ 是最典型的手滑。
3. **扇出没有相加**：$x$ 有两条出边，必须把 $-4.5$ 和 $+3.0$ 加起来。
   覆盖式写法只会留下一个，然后你会看到"两种遍历顺序算出两个不同答案"这种诡异现象。
4. **浮点精度要对齐**：手写和 autograd 都用 `float64`。如果 autograd 那边默认用 `float32`，
   随机点上两者会有 $10^{-5}\sim10^{-6}$ 量级的差异（实测 20 组随机点最大 7.5e-06），
   这时候"对不上"是精度问题不是公式问题。注意本例这组数是二进制精确可表示的，
   `float32` 也恰好给出 -1.5 / -2.25，所以别用这一组数去测精度。
5. **数值梯度的 $h$ 别乱取**：$h$ 太大截断误差大，太小舍入误差大，$h = 10^{-6}$ 是标量情况下的常用折中。

# 5. 结论

* 计算图把 $f = (xy + x^2)^2$ 拆成 $a = x^2 \to b = xy \to u = a+b \to f = u^2$ 四个基本运算之后，
  求导就是"沿边回传、每步乘局部导数、多路相加"。
* 手写 NumPy 反向传播得到 $\partial f/\partial x = -1.5$、$\partial f/\partial y = -2.25$，
  与解析式、中心差分、PyTorch autograd 四者一致。
* 与 autograd 的误差为 0（逐位相同），并且 autograd 生成的反向图（`PowBackward0 → AddBackward0 →
  {PowBackward0, MulBackward0}`）和手画的图结构完全对应，其中挂着两次的 `AccumulateGrad`
  就是"扇出要相加"的框架实现。

# 1. 网络结构、形状约定与参数初始化

## 全部张量的形状（N 个样本、输入 2 维、隐藏层 H 个神经元、输出 1 维）

| 记号 | 含义 | 形状 | 本例（N=8, H=3） |
| --- | --- | --- | --- |
| `X` | 输入（标准化后的两个特征） | (N, 2) | (8, 2) |
| `W1` | 第一层权重，**每一列是一个神经元** | (2, H) | (2, 3) |
| `b1` | 第一层偏置 | (H,) | (3,) |
| `Z1 = XW1 + b1` | 第一层的 logit | (N, H) | (8, 3) |
| `A1 = relu(Z1)` | 隐藏层激活 | (N, H) | (8, 3) |
| `W2` | 第二层权重 | (H, 1) | (3, 1) |
| `b2` | 第二层偏置 | (1,) | (1,) |
| `Z2 = A1W2 + b2` | 输出 logit | (N, 1) | (8, 1) |
| `P = σ(Z2)` | 预测概率（0~1） | (N, 1) | (8, 1) |
| `T` | 真实标签 | (N, 1) | (8, 1) |
| `L = BCE(P,T)` 取平均 | 损失 | () 标量 | () |
| `∂L/∂W1` … | 参数梯度 | 与参数**完全同形状** | (2,3)、(3,)、(3,1)、(1,) |

两条贯穿全篇的形状规则，出问题时最先看这两条：

1. **参数梯度的形状 = 参数本身的形状**（否则没法做 `W -= lr * dW`）；
2. **每一层的梯度形状 = 该层前向输出的形状**（因为梯度就是"损失对这个张量求导"）。

## 为什么 `W1` 写成 (2, H)，而 PyTorch 里存的是 (H, 2)

手写时用 `Z1 = X @ W1`，所以 `W1` 天然是 (输入维, 隐藏维)；而 `torch.nn.Linear(in, out)` 内部算的是
`x @ W.weight.T`，它把 weight 存成 (out, in)。两边只差一次转置。本例里为了能一一对应，
我们把 NumPy 的 `W1`、`b1`、`W2`、`b2` 直接搬进 torch，用同样的 `@` 写法搭图，
正是为了避开这层转置带来的误判。

## 参数的初始化值（本例）

```
W1 = [[ 0.125730, -0.132105,  0.640423]      b1 = [0, 0, 0]
      [ 0.104900, -0.535669,  0.361595]]      b2 = [0]
W2 = [[ 1.064712], [ 0.773288], [-0.574597]]
```

用标准初始化 $W \sim \mathcal{N}(0, \sqrt{2/\text{fan\_in}})$，偏置全 0。注意本例里第 2 个隐藏神经元
（列 `W1[:,1]`，下标从 0 起）对第 0 个样本的 `Z1` 是负的，ReLU 输出 0 → 它的梯度**恰好是 0**。
这不是 bug，是 ReLU 的正常现象（下一节会具体看到）。

# 2. NumPy 前向：四个公式，一步一个形状

```python
Z1 = X @ W1 + b1        # (N,2)@(2,H) + (H,)   → (N,H)   b1 靠广播加到每一行
A1 = relu(Z1)           # 逐元素，形状不变      → (N,H)
Z2 = A1 @ W2 + b2       # (N,H)@(H,1) + (1,)   → (N,1)
P  = sigmoid(Z2)        # 逐元素，值域 (0,1)    → (N,1)
per_sample = -(T*np.log(P) + (1-T)*np.log(1-P))  # (N,1) 每个样本一份损失
L  = per_sample.mean()                           # ()    标量
```

代入**单个样本**（N=1，x = (-0.315305, 0.958842)，t = 0）：

```
Z1 = [ 0.060939, -0.471969,  0.144784]     ← 第 2 个元素是负的
A1 = [ 0.060939,  0.0,       0.144784]     ← ReLU 把它置 0
Z2 = 0.060939×1.064712 + 0×0.773288 + 0.144784×(-0.574597) = -0.018310
P  = σ(-0.018310) = 0.495423               ← 几乎就是 0.5：刚初始化时模型一无所知
L  = -[0×log P + 1×log(1-P)] = -log(0.504577) = 0.6840341359
```

两点值得记下来：

* **广播**：`b1` 只有 (H,) 却能加到 (N,H) 上，靠的是广播。反向时这一步会"自动变成求和"——
  这正是 `db1 = dZ1.sum(axis=0)` 的来历：前向把一个常数复制了 N 份，反向就得把 N 份梯度加回去。
* **ReLU 的 0 是两种 0**：前向把负数变成 0，反向让这些位置的梯度恒为 0
  （$\partial A_1/\partial Z_1 = \mathbb{1}\{Z_1>0\}$）。本例第 2 个神经元那一列的梯度全是 0 就是这么来的。

# 3. 计算图与反向传播：每个参数的梯度怎么来的

## 计算图（和 `03_nn_compute_graph.png` 对应）

```
        W1       b1                        W2       b2
         │        │                         │        │
X ──────►┤ Z1 = XW1 + b1 ├──►┤ A1 = relu(Z1) ├──►┤ Z2 = A1W2 + b2 ├──►┤ P = σ(Z2) ├──►┤ L = BCE+mean ├
(N,2)        (N,H)                (N,H)                (N,1)               (N,1)               ()
```

反向沿着这张图倒着走，每一步只做两件事：**取本节点的局部导数**、**乘上从上游带下来的梯度**。
这个网络里有两种"一对多"，它们正好都在反向时变成了"求和"：

1. **同一份参数被 N 个样本共用**：前向里一份 `W1` 参与了 N 条路径的计算，反向就得把 N 份梯度加起来——
   `dW1 = XᵀdZ1` 里的矩阵乘干的就是这件事；
2. **偏置被广播复制了 N 份**：`b1` (H,) 被复制到 (N,H) 的每一行，反向用 `sum(axis=0)` 加回来。

（实践 1 里 `x` 同时流向 `x²` 和 `x·y` 那种"扇出"，在这个网络里的对应物就是上面这两条。）

## 局部导数表（记这五行就够）

| 节点 | 前向 | 局部导数 |
| --- | --- | --- |
| Linear（第一层） | $Z_1 = XW_1 + b_1$ | $\partial Z_1/\partial W_1 = X^{\mathsf T}$；$\partial Z_1/\partial b_1 = \mathbf{1}$；$\partial Z_1/\partial X = W_1^{\mathsf T}$ |
| ReLU | $A_1 = \max(Z_1, 0)$ | $\partial A_1/\partial Z_1 = \mathbb{1}\{Z_1 > 0\}$（逐元素 0/1 掩码） |
| Linear（第二层） | $Z_2 = A_1W_2 + b_2$ | $\partial Z_2/\partial W_2 = A_1^{\mathsf T}$；$\partial Z_2/\partial b_2 = \mathbf{1}$；$\partial Z_2/\partial A_1 = W_2^{\mathsf T}$ |
| Sigmoid | $P = \sigma(Z_2)$ | $\partial P/\partial Z_2 = P(1-P)$ |
| BCE + mean | $L = \frac1N\sum_i \ell_i$ | $\partial L/\partial P = -\frac1N\big[T/P - (1-T)/(1-P)\big]$；$\partial L/\partial \ell_i = 1/N$ |

## 逐步反向（形状写在每一步）

```python
dZ2 = (P - T) / N              # (N,1)  ← Sigmoid 与 BCE 的导数相乘后 P(1-P) 被约掉，见第 7 节 Q3
dW2 = A1.T @ dZ2               # (H,N)@(N,1) → (H,1)   和 W2 同形状
db2 = dZ2.sum(axis=0)          # (1,)                 batch 维被"挤掉"，和 b2 同形状
dA1 = dZ2 @ W2.T               # (N,1)@(1,H) → (N,H)   和 A1 同形状
dZ1 = dA1 * (Z1 > 0)           # (N,H)                ReLU 掩码，负的那一半清零
dW1 = X.T @ dZ1                # (2,N)@(N,H) → (2,H)   和 W1 同形状
db1 = dZ1.sum(axis=0)          # (H,)                 和 b1 同形状
```

每一步为什么长这样，只看"谁需要转置、谁需要求和"就够：

* `dW2 = A1ᵀ·dZ2`：$Z_2$ 的第 $i$ 行是 $A_{1,i}\cdot W_2$，所以每个样本都贡献一份梯度
  $A_{1,i}^{\mathsf T}\,dZ_{2,i}$，`A1.T @ dZ2` 干的正是"对所有样本求和"这件事；
* `db2 = dZ2.sum(axis=0)`：前向 `+ b2` 是对每个样本加同一个常数，反向就得把 batch 维加起来；
* `dZ1 = dA1 * (Z1 > 0)`：ReLU 的局部导数，逐元素相乘。

## 单样本的具体数值（N = 1）

```
dZ2 = P - T = 0.495423 - 0 = 0.495423
dW2 = A1ᵀ·dZ2 = [ 0.030191, 0.0, 0.071729 ]          ← 中间那项 0：该神经元在这个样本上是"死"的
db2 = 0.495423
dA1 = dZ2·W2ᵀ = [ 0.527482, 0.383134, -0.284670 ]
dZ1 = dA1 ⊙ 1{Z1>0} = [ 0.527482, 0.0, -0.284670 ]   ← 第 2 个神经元被掩码清零
dW1 = Xᵀ·dZ1 = [[-0.166318, 0.0,  0.089757],
                [ 0.505772, 0.0, -0.272952]]          ← 同样是一整列 0
db1 = dZ1.sum(axis=0) = [ 0.527482, 0.0, -0.284670 ]
```

可以拿一个元素手工核一遍：$\partial L/\partial W_{1,00} = x_0 \cdot dZ_{1,0}
= (-0.315305)\times 0.527482 = -0.166318$ ✔

## N = 1 时的两个"巧合"（也是坑）

* 因为 $1/N = 1$，"取平均"和"求和"在这个样本上看不出区别，所以**单个样本验不出 `mean/sum` 这类错误**；
* 只有 $N=1$ 才有 $db_2 = P - t$（`sum(axis=0)` 只加一项）。换成 batch 就不成立了。

# 4. PyTorch autograd 复核：形状、数值、最大绝对误差

用**完全一样的参数和输入**在 PyTorch 里重搭一遍：

```python
tZ1 = tX @ tW1 + tb1        # tX / tW1 / tb1 … 都由 NumPy 的数组转来，dtype=float64
tA1 = torch.relu(tZ1)
tZ2 = tA1 @ tW2 + tb2
tL  = F.binary_cross_entropy(torch.sigmoid(tZ2), tT)    # reduction='mean'（默认）
tL.backward()
```

## 逐项对比（单个样本）

| 项 | 形状 | NumPy 手写 | PyTorch autograd | 中心差分 | 最大绝对误差 | 一致？ |
| --- | --- | --- | --- | --- | --- | --- |
| `∂L/∂W1` | (2,3) | `[[-0.166318, 0, 0.089757], [0.505772, 0, -0.272952]]` | 同左 | 同左 | 0.00e+00 | ✔ |
| `∂L/∂b1` | (3,) | `[0.527482, 0, -0.284670]` | 同左 | 同左 | 0.00e+00 | ✔ |
| `∂L/∂W2` | (3,1) | `[0.030191, 0, 0.071729]` | 同左 | 同左 | 0.00e+00 | ✔ |
| `∂L/∂b2` | (1,) | `[0.495423]` | 同左 | 同左 | 0.00e+00 | ✔ |
| `L` | () | `0.684034135879` | `0.684034135879` | — | 0.00e+00 | ✔ |

小 batch（N = 8）同样全部对上，最大绝对误差 **5.55e-17**（就是浮点最后一位的舍入）；
与中心差分（完全不依赖自动微分的第三方）的最大绝对误差 **6.18e-11**，属于数值微分方法自身的精度
（截断误差 + 舍入误差），不是公式错。**三个互相独立的来源都指向同一组数，才敢说"梯度算对了"。**

## autograd 自己建的反向图

```
- BinaryCrossEntropyBackward0      ← 我们的 BCE + mean
  - SigmoidBackward0               ← 我们的 P = σ(Z2)
    - AddBackward0                 ← Z2 = A1W2 + b2
      - MmBackward0                ← 矩阵乘 A1 W2
        - ReluBackward0            ← A1 = relu(Z1)
          - AddBackward0           ← Z1 = XW1 + b1
            - MmBackward0          ← 矩阵乘 X W1
              - AccumulateGrad     ← 梯度落到 W1.grad
            - AccumulateGrad       ← 梯度落到 b1.grad
        - AccumulateGrad           ← 梯度落到 W2.grad
      - AccumulateGrad             ← 梯度落到 b2.grad
```

结构和我们画的计算图逐层对应，多出来的只有每个参数下的 `AccumulateGrad`——它就是
"把这条边回传的梯度**累加**到 `.grad`"这件事（所以训练循环里必须 `optimizer.zero_grad()`，
否则梯度会一直累加）。实践 1 里手写的 `grads["x"] = grad_from_a + grad_from_b`，
在这里是框架替你做的。

另外注意 `dtype`：两边都用 `float64` 时误差是 0；如果 autograd 那边默认用 `float32`，
同一个样本的梯度就会出现 1e-7 量级的差异——那不是公式错，是精度错。

# 5. 换成一个 batch：哪些公式、哪些形状变了

同一个网络、同一组参数，输入从 1 个样本换成 8 个样本（形状对照见 `05_nn_batch_effect.png`）：

| 张量 | N = 1 | N = 8 |
| --- | --- | --- |
| `X` | (1, 2) | (8, 2) |
| `Z1` / `A1` | (1, 3) | (8, 3) |
| `Z2` / `P` | (1, 1) | (8, 1) |
| `W1` / `∂L/∂W1` | (2, 3) | **(2, 3) 不变** |
| `b1` / `∂L/∂b1` | (3,) | **(3,) 不变** |
| `W2` / `∂L/∂W2` | (3, 1) | **(3, 1) 不变** |
| `b2` / `∂L/∂b2` | (1,) | **(1,) 不变** |

**变的只有"带样本数的那一维"，参数形状和参数梯度形状永远不变。**

公式上真正变化的只有三处：

1. **$1/N$ 因子**：loss 从"单个样本的损失"变成 8 个样本的平均，反向多出一个 $1/N$。
   8 个样本各自的损失是 `[0.684034, 0.486617, 0.939918, 0.696452, 0.693980, 0.591440, 0.586051, 0.953278]`，
   平均 $L = 0.7039711892$（注意：8 个样本里恰好只有第 0 个和上面单样本那次相同）。
2. **$\partial L/\partial b$ 要对 batch 求和**：`db1 = dZ1.sum(axis=0)`、`db2 = dZ2.sum(axis=0)`。
   偏置在所有样本间共享，所以它的梯度必须把 batch 维消掉。
3. **$\partial L/\partial W$ 的矩阵乘多一维**：`Xᵀ(2,N) @ dZ1(N,H) → (2,H)`，
   batch 维在矩阵乘里被自动求和消掉——这正是"所有样本共享同一个权重"的表达。

**没变的**：逐元素操作的公式一个字都没改（ReLU 掩码、$P(1-P)$、`dZ2 = (P-T)/N` 的逐元素形式）。
这才是"写完单样本、改成 batch 只动三行"的原因。

## 用具体数字核一遍 `dW2`（batch 版）

$\partial L/\partial W_{2,00} = \frac1N\sum_{i=1}^{8} A_{1,i0}(p_i - t_i)$，逐项展开：

```
dW2[0] = (1/8) × Σ_i A1[i,0] · (p_i - t_i)
       = 0.060939×( 0.061928)   ← 第 1 个样本（t=0）
       + 0.263962×(-0.076167)   ← 第 3 个样本（t=1）
       + 0.021365×( 0.062706)
       + 0.100302×( 0.062552)
       + 0.050264×(-0.055809)
       + 0.255630×(-0.076816)
       ≈ -0.03116               ← 与程序打印的 dW2[0] = -0.031159 一致
```

（只有 6 项是因为第 2、7 个样本在该神经元上被 ReLU 置 0，$A_1 = 0$，直接贡献 0。）这里的 $p_i - t_i$ 就是每个样本的
"预测误差"，所以 $\partial L/\partial W_2$ 的含义是**"误差 × 对应的隐藏层激活"在 batch 上的平均**——
正是实践 1 里"扇出求和"的思想在 batch 维上的重复。batch 里还有 7/24 个 `Z1` 元素被 ReLU 置 0
（第 6 号样本三个神经元全灭），它们的梯度贡献同样是 0，隐藏层的"稀疏"在这里是看得见的。

# 6. 数值对不上时怎么查（附三个故意写错的版本）

脚本里特意写了三个"错误版本"，先把症状认全：

| 错误 | 症状 | 怎么识别 |
| --- | --- | --- |
| loss 用 `sum` 而不是 `mean` | 13 个梯度**全部都**放大 8 倍（= N），形状完全正确 | 算"sum 版梯度 ÷ mean 版梯度"，所有项都等于同一个常数 N → 求平均方式错了 |
| 转置写反（`dW1 = dZ1ᵀ @ X`） | 形状直接变成 (3,2)，和 `W1` 的 (2,3) 相减立刻报广播错误 | 形状对不上 → 先怀疑维度顺序/转置 |
| 忘记对 batch 求和（`db1` 少写 `sum(axis=0)`） | 拿到 (8,3) 而 `b1` 是 (3,)；N=1 时**完全看不出问题** | 只有偏置相关项错，且错法随 batch 大小变化 |

排查顺序（与 `04_nn_grad_check.png` 里那段一致）：

1. **形状对不上** → 转置/维度顺序问题，先把每一步的形状 `print` 出来；
2. **形状对，但所有项都差同一个固定倍数** → 求平均方式（`sum` vs `mean`）；
3. **只有一部分元素差** → 某个逐元素操作写错了（ReLU 掩码位置、广播方向、张冠李戴把 `A1` 当成 `X`）；
4. **只差 1e-5 ~ 1e-8** → 十有八九是精度：`dtype` 用了 `float32`，或数值微分的 $h$ 没选好。

还有个更省事的办法：把中间量的梯度（`dZ2`、`dZ1`）也一起打印对比，从后往前找**第一个**不一致的中间量，
问题就在那个节点对应的那一步。本例里 `Z1/A1/Z2/P` 的中间量最大差都是 0.00e+00，
说明前向本身就是对的。

# 7. 趁热打铁

**Q1 前向传播时为什么要保存每一层的输入或输出？反向传播会在哪里用到它们？这和显存有什么关系？**

因为反向要用的是"**局部导数在该点的取值**"，而局部导数依赖前向算出来的值：

| 反向用到的量 | 依赖的前向结果 | 用途 |
| --- | --- | --- |
| $P(1-P)$ | `P`（或 `Z2`） | Sigmoid 的导数 |
| $\mathbb{1}\{Z_1>0\}$ | `Z1` 的符号 | ReLU 的掩码 |
| `A1ᵀ·dZ2` | `A1` | 第二层权重的梯度 |
| `Xᵀ·dZ1` | `X` | 第一层权重的梯度 |

这也是"为什么必须有 cache"：不保存就得在反向时重算（时间换空间），框架里的 `ctx.save_for_backward`
就是干这个的。而这些中间张量的形状都是 (N, H) 或 (N, 1)，**显存占用与 batch 大小、层宽成正比**，
所以 batch 越大越吃显存——这正是"梯度累积"（几个小 batch 累加出大 batch 的效果）和
"梯度检查点"（不存激活，反向时重算）两种技巧的由来。

**Q2 链式法则怎样把损失函数的梯度传回第一层权重？请结合自己的计算图说明。**

从 $L$ 出发沿图往回走，每经过一个节点就乘上它的局部导数，一路乘到底：

$$\frac{\partial L}{\partial W_1} = X^{\mathsf T}\cdot\mathbb{1}\{Z_1>0\}\odot\left(\frac{P-T}{N}\,W_2^{\mathsf T}\right)$$

即把四段的局部导数按"先来的先乘"串起来：BCE 与 Sigmoid 合成 `(P-T)/N` → 乘 $W_2^{\mathsf T}$ 穿过第二层 →
乘 ReLU 掩码 → 乘 $X^{\mathsf T}$（同时把 batch 维求和消掉）。$W_1$ 离 loss 最远，但链式法则不关心距离，
它只关心"路径上经过了哪些节点"——这正是"计算图 + 反向传播"能把任意深的网络变成机械化乘法的原因。

**Q3 二元交叉熵与 Sigmoid 配合后，loss 对 logit 的梯度是什么？这个结果为什么方便反向传播？**

$$\frac{\partial L}{\partial Z_2} = \frac{\partial L}{\partial P}\odot\frac{\partial P}{\partial Z_2}
= -\frac1N\Big[\frac{T}{P}-\frac{1-T}{1-P}\Big]\odot P(1-P) = \frac{P-T}{N}$$

（化简过程：$-\big[T(1-P)-(1-T)P\big] = -(T - TP - P + TP) = P - T$，$P(1-P)$ 被完全约掉。）

方便之处有三个：

1. **省事**：$\partial L/\partial P$ 里的 $1/P$ 和 $1/(1-P)$ 与 $P(1-P)$ 相乘后彻底消失，
   只剩一个减法——不需要任何除法；
2. **数值稳**：$P$ 接近 0 或 1 时 $1/P$ 会爆掉（直接写 `log(sigmoid(z))` 就危险了）。
   化简后这类项会自动"消失"（$P\to 1$ 且 $t=1$ 时梯度 $\to 0$），这也是框架里
   `BCEWithLogitsLoss` 直接吃 logits、内部走等价稳定公式的原因；
3. **形式统一**：结果就是"预测减标签"，和平方误差配线性层得到的 $(\hat y - y)$ 形态一致，
   "误差乘以输入"的直觉继续成立。

脚本里两条路都算了：分开算（$dL/dP \times P(1-P)$）与融合写法 `(P-T)/N`，两者之差是 0.00e+00。

**Q4 NumPy 梯度与 PyTorch 梯度出现差异时，你会怎样判断问题出在公式、矩阵转置、广播还是损失的求平均方式？**

用"**症状 → 病灶**"逐层排除（第 6 节那张表就是这个用法）：

* **形状对不上** → 转置/维度顺序（比如 `dW1` 该用 $X^{\mathsf T}$ 却忘了转置）；形状对了但某几项错，
  多半是广播方向或张冠李戴（把 `A1` 当 `X` 用）；
* **形状对、所有元素同比例错** → 求平均方式（`sum` vs `mean`，比值恒为 N）；
* **只有部分元素错** → 逐元素环节（ReLU 掩码位置、掩码写反）；
* **只差 1e-7 上下** → 精度：`float32`，或数值微分的 $h$ 不当，不是公式。

再加上"从后往前找第一个不一致的中间量"这一招，基本能定位到具体某一行。

**Q5 完成两次验证后，你现在怎样理解 `loss.backward()`？它替我们保存和完成了哪些工作？**

`backward()` 相当于把这次实践里手写的三件事一次做完：

1. **保存**：前向时每个算子把反向需要的量存进自己的 `ctx`（Sigmoid 存输出 `P`、ReLU 存 `Z1` 的符号、
   矩阵乘存参与运算的两个矩阵），也就是我们手写的 `cache` 字典；
2. **遍历**：从 `loss` 的 `grad_fn` 出发按拓扑逆序遍历整张图（手写时我们是"照图的倒序依次写"），
   每个节点调用自己的 `backward()` 算"上游梯度 × 局部导数"；
3. **累加与归约**：把每条边回传的梯度**累加**到对应叶子的 `.grad`（节点就叫 `AccumulateGrad`），
   并按下游形状要求自动做求和/广播归约（`db1 = dZ1.sum(axis=0)` 就是它自动做的）。

它**不**做的事同样要记住：不清空 `.grad`（所以要 `zero_grad()`）、不决定损失怎么平均
（那是你在写 loss 时定的）、不更新参数（那是 `optimizer.step()`）。所以训练三步曲永远是
`zero_grad() → backward() → step()`。这次能把 `backward()` 一行一行对应到自己的公式上，
才算真的理解了它。

# 8. 遇到过的报错与踩坑记录

1. **`UnicodeEncodeError: 'gbk' codec can't encode character '\u2202'`**
   直接 `python nn_backprop.py` 时，Windows 控制台默认 GBK(936)，`print` 里的 `∂`、`σ`、`⊙` 直接抛错。
   解决：脚本开头 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。
2. **matplotlib 警告 `Glyph 7488 (\N{MODIFIER LETTER CAPITAL T}) missing from font(s) Microsoft YaHei`**
   图里用了上标 `ᵀ`（U+1D40），微软雅黑没有这个字形，会画成方框。解决办法：图内文字统一写成 `X^T`。
3. **`Could not save font_manager cache [Errno 13] Permission denied`**
   matplotlib 想在用户目录写字体缓存却写不进去。解决：把 `MPLCONFIGDIR` 指到临时目录。
4. **`Windows fatal exception: code 0xc06d007f` / `OMP: Error #15`**
   老问题（Task 1、实践 1 也遇到过）：不 `conda activate` 而直接跑 `python.exe` 时，MKL 找不到 DLL，
   或与 torch 自带的 libiomp5 冲突，而且没有任何 Python 报错。脚本开头的"环境自举"
   就是为它准备的（补 PATH + `KMP_DUPLICATE_LIB_OK=TRUE`）。
5. **打印形状时把 `(2, 3)` 打成 `(2)`**
   我自己写的小工具函数踩的坑：`np.shape((2, 3))` 会把元组当成"长度为 2 的序列"，于是返回 `(2,)`。
   要先用 `isinstance(shape, tuple)` 拦一下，不能直接交给 `np.shape`。
6. **为什么 `dW1` 里有一整列是 0？**
   一开始以为算错了，其实是那个神经元在该样本上被 ReLU 置 0（$A_1 = 0$ 且掩码为 0），
   它的梯度本来就该是 0。**ReLU 的梯度为 0 是正常现象**；但如果整批数据都没能让某个神经元激活，
   就成了"dead ReLU"（常见于学习率过大），那是要处理的。
7. **`F.binary_cross_entropy` 和 `F.binary_cross_entropy_with_logits` 用哪个？**
   前者要先自己 `sigmoid`（与本题手写图一一对应，方便对拍）；后者直接吃 logits，
   内部走更稳的等价公式，实际训练应该用后者。正常数值范围内两者梯度一致。
8. **还不太理解、想继续查的点**
   * `backward()` 到底在多大程度上"用完就释放"了中间缓存（`retain_graph` 与内存峰值的关系），
     想做个实验量一量；
   * 偏置梯度"沿 batch 维求和"背后的统一规律：目前的理解是"前向广播了几份，反向就把几份加回来"，
     希望能找到一个更一般的表述（比如用 `einsum` 把所有情形写成同一个形式）。

# 9. 结论

* 一个 13 个参数的两层网络（`X → Linear → ReLU → Linear → Sigmoid → BCE`）：
  前向是 (N,2) → (N,3) → (N,3) → (N,1) → (N,1) → ()；
  反向是 `dZ2 = (P-T)/N` → `dW2 = A1ᵀdZ2`、`db2 = ΣdZ2` → `dA1 = dZ2W2ᵀ` →
  `dZ1 = dA1 ⊙ 1{Z1>0}` → `dW1 = XᵀdZ1`、`db1 = ΣdZ1`。
* 手写 NumPy 梯度与 PyTorch autograd 的最大绝对误差：单个样本 **0.00e+00**，
  8 个样本的 batch **5.55e-17**；与中心差分 6.18e-11（数值微分自身的精度）。三方差分一致，公式正确。
* 单个样本 → 小 batch 只改三处：**$1/N$、对 batch 维求和、矩阵乘多一维**；
  参数形状与参数梯度形状不变，逐元素公式（ReLU 掩码、$P(1-P)$）一个字不用改。
* `loss.backward()` 替我们做了"保存中间量 + 逆序遍历 + 按边累加"三件事；
  它不做的是清空 `.grad`、决定损失如何平均、更新参数。
